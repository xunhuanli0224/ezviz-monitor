# 萤石云监控墙（Ezviz Wall）

本地运行的多路萤石云监控查看工具。支持多画面同屏、独立窗口多开、逐路失败报错，并可一键生成**访问失败总结报告**（JSON / CSV / Markdown）。

---

## 一、能力概览

| 能力 | 说明 |
| --- | --- |
| 多画面同屏 | 1 / 4 / 9 / 16 分屏布局，支持任意数量通道（超出分屏数量自动滚动） |
| 多开查看 | ① 同一页面多画面；② 每路「独立窗」单独弹出播放窗口；③ 浏览器多标签同时打开 |
| 逐路错误提示 | 每路通道独立状态机，失败时在画面中央显示**错误码 + 错误描述 + 处理建议 + 重新连接** |
| 自动续期 | 直播地址默认 7200 秒有效，剩余不足 90 秒时自动重新取址，避免画面中断 |
| 批量检测 | 「重新检测全部」串行巡检所有通道，记录耗时、错误码与重试次数 |
| 失败报告 | 概览指标 + 失败归类统计 + 失败明细表 + 逐条处理建议 + 结论与风险提示，可导出 CSV / Markdown 并归档 |

## 二、目录结构

```
ezviz_monitor/
├── 启动监控墙.bat        # Windows 一键启动（自动查找 python / py -3）
├── start.sh              # macOS / Linux 一键启动
├── portable.py           # 打包「干净可移植副本」为 zip（剔除凭证与报告）
├── build_exe.py          # 打包为单文件可执行程序（免安装 Python）
├── server.py             # 本地服务端：接口代理、Token 续期、报告落盘（仅标准库）
├── config.json           # 首次运行自动生成，保存 AppKey / AppSecret / Token（本机）
├── web/
│   ├── index.html        # 主界面
│   ├── app.js            # 播放引擎、状态机、报告生成
│   ├── style.css
│   ├── player.html       # 独立窗口播放页
│   └── vendor/
│       └── hls.min.js    # 本地播放内核（hls.js 1.5.17，离线可用）
├── dist/                 # portable.py 生成的源码移植包
├── dist_exe/             # build_exe.py 生成的可执行程序
└── reports/              # 访问失败报告归档（自动创建）
```

## 三、快速开始

### 1. 环境要求

- Windows / macOS / Linux
- Python 3.8 及以上（**无需安装任何第三方库，不需要 pip install**）
- Chrome / Edge 等现代浏览器（需支持 MSE 的 H.264 解码）
- 播放内核 hls.js 已内置在 `web/vendor/`，**不依赖外网 CDN**

> 完整依赖清单与移植步骤见 [十一、依赖与移植](#十一依赖清单与移植部署)。

### 2. 启动

```
双击 启动监控墙.bat
```

或命令行：

```bash
python server.py                 # 默认 8770 端口，自动打开浏览器
python server.py --port 9000     # 指定端口
python server.py --no-browser    # 不自动打开浏览器
```

启动成功后控制台会显示服务地址，浏览器自动打开 `http://127.0.0.1:8770/`。

> **注意：不要把 `web/index.html` 双击用浏览器打开。** `file://` 方式会被浏览器安全策略拦住，无法与本地服务通信。页面检测到 `file://` 时会直接给出提示。

> **关于启动脚本的语言**：`启动监控墙.bat` 内部提示为英文，是刻意为之——cmd.exe 按本地代码页（中文 Windows 为 GBK）解析批处理文件，若文件内是 UTF-8 中文，会被拆成乱码命令导致服务无法启动。程序自身的界面与日志仍为中文。

服务仅监听 `127.0.0.1`，不对外网暴露。端口被占用时会自动向后寻找可用端口。

### 3. 配置凭证（使用直链时可不配置）

点击右上角 **＋ 添加监控 → 设置凭证**，填写：

- **AppKey**、**AppSecret**：在[萤石开放平台](https://open.ys7.com)控制台创建应用后获得
- 保存时工具会自动调用 `token/get` 验证并缓存 Token，成功后会提示 Token 有效期

> 凭证仅保存在本机 `config.json`，不上传任何第三方服务器。建议将本目录加入版本控制忽略列表。

## 四、添加监控通道

三种方式，可混用：

**① 批量粘贴**（最常用）

```
序列号:通道:名称
FQ1234567:1:大门口
FQ1234567:2:仓库
https://hls.example.com/live/xxx.m3u8
```

- `序列号:通道` 最少两段；第三段起为名称（可含空格，但不能含冒号）
- 以 `http(s)://` / `rtmp://` / `ezopen://` 开头的行按**直链**处理，协议自动识别
- 一行一个通道，空行与 `#` 开头的行会被忽略

**直链格式（无需 AppKey / AppSecret）**

萤石开放平台返回的 HLS 播放地址可直接粘贴，无需配置凭证：

```
https://open.ys7.com/v3/openlive/GD0084509_1_1.m3u8?expire=1805358646&id=956228527886172160&t=ca0abfa...
```

工具会自动完成以下处理：

| 处理项 | 说明 |
| --- | --- |
| 容错提取 | 前后带引号、括号、中文标点或"链接：xxx"等说明文字，都能自动提取出 URL |
| 名称推导 | 从路径 `GD0084509_1_1` 识别为「直链 GD0084509 通道1」 |
| 有效期解析 | 读取 `expire` 参数（Unix 秒），卡片底栏实时显示剩余有效期；已过期直接判失败并报 `URL_EXPIRED`，不再徒劳请求 |
| 协议识别 | `.m3u8` → HLS；`rtmp://` → 明确提示不支持；`ezopen://` → 需 EzUIKit |

> 实测：该类链接的播放列表与 TS 分片均返回 `Access-Control-Allow-Origin: *`，浏览器可直连播放，无需任何代理。

**② 从设备列表**：自动读取当前账号设备 → 查看通道 → 逐个添加

**③ 演示模式**：空界面点击「载入演示通道」，或访问 `http://127.0.0.1:8770/?demo=1`。演示通道为本地 canvas 测试图（无真实码流），其中固定含 1 路模拟失败通道，用于验证报错与报告流程。

## 六、报错机制

每路通道独立维护状态：`待播放 → 取流中 → 缓冲中 → 在线`，异常时进入 `失败`，画面覆盖层显示：

```
[20007]  设备不在线
设备离线：检查供电、网线 / Wi-Fi、路由器是否正常，必要时重启设备。
              [ 重新连接 ]
```

**失败阶段划分**（报告中「失败阶段」字段）：

- `config`：本地未配置凭证
- `network`：本机到萤石服务器的网络不可达
- `api`：平台返回业务错误码（设备离线、无权限、不支持协议等）
- `play`：已拿到地址但码流无法播放（地址过期、CDN 拒绝、解码失败）

内置错误码映射覆盖常用场景（`20002/20007/20008/20010/20011/20018/20032/10017/10030/49999/60020` 等）。未收录的返回码会原样展示并标注「其他」归类——**错误码最终含义以萤石开放平台官方文档为准**。

## 七、访问失败报告

点击右下角 **生成报告**（或 `Ctrl/Cmd + R`）打开报告抽屉：

1. **概览**：通道总数 / 访问成功 / 访问失败 / 成功率
2. **失败归类统计**：按 设备状态、凭证鉴权、设备与权限、协议能力、请求参数、网络、播放、服务端 分类并给出占比
3. **失败明细**：通道名称、序列号、通道号、协议、错误码、错误描述、归类
4. **结论与建议**：自动生成结论文本——定位占比最高的失败类型，输出针对性处置建议，成功率低于 60% 时追加风险提示

**导出方式**：

- 「保存到 reports/」→ 同时写入 `.json` `.csv` `.md` 三份，文件名 `access_report_YYYYMMDD_HHMMSS.*`
- 「导出 CSV」/「导出 Markdown」→ 浏览器直接下载

> 报告基于**当前画面状态**生成。要得到可用于归档的正式报告，请先点「重新检测全部」，等待全部通道出结果后再保存。

## 八、常见问题

**Q：双击 `启动监控墙.bat` 窗口一闪就消失了，浏览器没打开？**
按顺序排查：

1. 在工具目录按住 `Shift` 右键 → 「在此处打开 PowerShell/终端」，执行 `python server.py`，直接看报错信息；
2. 若提示"不是内部或外部命令"，说明 Python 未加入 PATH，重装时勾选 "Add python.exe to PATH"；
3. 若是批处理报出 `'xxx' 不是内部或外部命令` 且文字是乱码，说明 .bat 文件被编辑器以 UTF-8 重新保存过——本工具已改为纯 ASCII 批处理，请勿修改其编码。

**Q：页面顶部提示"请通过本地服务访问"？**
说明是用 `file://` 直接打开了 `web/index.html`。必须通过 `启动监控墙.bat` 或 `python server.py` 启动，再访问 `http://127.0.0.1:8770/`。

**Q：粘贴直链后画面一直"缓冲中"然后超时？**
先用浏览器直接打开该 `m3u8` 地址验证：能下载到文本说明链接有效。若链接有效但仍无法出流，通常是设备未推流或分片 CDN 拒绝了当前网络。点击「重新连接」重试；连续失败请重新获取新的播放地址。

**Q：报 `60020` / `20032`，设备不支持 HLS？**
部分设备或账号未开通 HLS 能力。可在「添加监控」中把协议切为 `ezopen`——但 `ezopen` 需要萤石官方 EzUIKit 播放内核，本工具未内置，此时会明确提示而非静默黑屏。推荐做法：先在萤石开放平台确认该设备支持的协议类型。

**Q：画面一直「缓冲中」然后超时？**
地址已成功下发但码流未就绪，常见于设备休眠、上行带宽不足、或 CDN 边缘节点未就绪。点击「重新连接」；连续失败可把清晰度降为「流畅」。

**Q：报 `NETERR` 无法连接萤石开放平台？**
本机出网被限制。企业网络需放行 `open.ys7.com:443`；使用代理的环境请确认系统代理对 Python 生效。

**Q：Token 频繁失效？**
确认本机系统时间准确（与标准时间偏差应小于 5 分钟）；确认同一 AppKey 未被其他程序反复刷新 Token。

**Q：为什么不用浏览器直接调萤石接口？**
萤石 OpenAPI 不返回 CORS 头，且 `AppSecret` 放在前端会泄露。因此由本地服务端代理请求，前端只与 `127.0.0.1` 通信。

**Q：最多支持多少路？**
播放侧受浏览器解码能力限制，建议同屏不超过 16 路（1080P）。接口侧受开放平台 QPS 与并发限制约束——本工具批量巡检时每路间隔 250ms 以防限流。

## 九、已知限制

1. 仅支持 **HLS（m3u8）** 在浏览器内播放；RTMP、FLV、ezopen 会给出明确不支持提示。
2. 不内置录像回放、云台控制、对讲等能力，仅做实时预览与可用性巡检。
3. 未做用户体系与多租户隔离，定位为**单机单人的运维工具**，请勿直接部署到公网。
4. 报告中的「访问成功」指**成功获取直播地址并出流**，不等同于画质/流畅度评估。

## 十一、依赖清单与移植部署

### 1. 依赖清单

**运行期依赖只有两项，且均为目标机既有环境：**

| 依赖 | 要求 | 是否需安装 | 说明 |
| --- | --- | --- | --- |
| Python | 3.8+ | 需目标机已有 | 仅用标准库：`http.server`、`urllib`、`json`、`csv`、`socket`、`threading`、`zipfile`。**无 requirements.txt，无需 pip** |
| 浏览器 | Chrome / Edge 90+ | 需目标机已有 | 需支持 MSE 的 H.264 解码；国产双核浏览器（QQ/360 极速模式）通常可用 |
| hls.js | 1.5.17 | **否，已内置** | 位于 `web/vendor/hls.min.js`（414 KB）。加载顺序为本地优先，CDN 仅在本地文件缺失时兜底 |

> 若目标机完全没有 Python，可打包成免安装的可执行程序，见 [十二、打包为免安装可执行程序](#十二打包为免安装可执行程序)。

**网络依赖：**

| 目标 | 用途 | 说明 |
| --- | --- | --- |
| `open.ys7.com` | OpenAPI 鉴权、取流地址 | 仅使用「API 取址」模式时需要 |
| `*.ys7.com`（含 `aljhv7.ys7.com:8102` 等分片域名） | 拉取 m3u8 与 TS 分片 | 直链与 API 模式都需要；企业防火墙需放行 `*.ys7.com:443` 与 `:8102` |
| 无 | — | 播放本身**不再依赖任何 CDN** |

**不依赖的东西（常见误解）：**

- 不需要 Node.js、npm、Web 服务器（Nginx/IIS）、数据库
- 不需要萤石官方 EzUIKit / EzvizPlayer 播放内核
- 不需要管理员权限，不写注册表，不在系统目录留文件
- 不需要开放公网端口（仅监听 `127.0.0.1`）

### 2. 移植步骤

**推荐做法：用打包脚本生成干净副本。**

```bash
python portable.py                # 生成 dist/ezviz_monitor_portable_<时间戳>.zip，已剔除凭证与历史报告
python portable.py --with-config  # 连本机 config.json 一起打包（仅限自有设备间迁移）
```

打包产物约 166 KB，目录结构完整、路径全部为相对路径（不含任何绝对路径或用户目录引用）。实测：解压到任意路径直接启动，`reports/` 与 `config.json` 会在新位置自动重建。

**目标主机上的三步：**

1. 安装 Python 3.8+（Windows 安装时勾选 **Add Python to PATH**）
2. 解压 zip，得到 `ezviz_monitor` 目录
3. 启动：
   - Windows：双击 `启动监控墙.bat`
   - macOS / Linux：`sh start.sh`（或 `chmod +x start.sh` 后双击）
   - 任意平台：`python server.py --port 8770`

首次运行若为 API 取址模式，需重新填 AppKey / AppSecret（`py portable.py` 默认不带 `config.json`，避免密钥外泄）。**直接用 m3u8 直链则无需任何凭证。**

### 3. 移植注意事项

| 事项 | 说明 |
| --- | --- |
| `config.json` 含密钥 | 打包默认剔除。手工拷贝目录时请先清空或删除该文件 |
| 端口占用 | 默认 8770，被占用会自动向后寻找空闲端口；也可 `--port 9000` 指定 |
| 多实例 | 不同端口启动即可并行多开，各自独立的配置与报告目录 |
| 无 Python 环境 | 用 `python build_exe.py` 生成免安装可执行程序，目标机只放一个 exe 即可，详见第十二节 |
| 跨平台一致性 | 服务端无任何 Windows 专有调用（无注册表、无 `startfile`、无 `chcp` 依赖），Linux/macOS 可直接运行 |
| 只读介质 | 配置写入失败只告警不崩溃；报告目录不可写时保存报告返回明确错误码 `REPORT_DIR`，预览与播放不受影响 |

### 4. 移植后自检

启动后访问 `http://127.0.0.1:8770/api/state`，返回 JSON 中：

- `version` 有值 → 服务正常
- `hasCreds: true/false` → 凭证是否已配置（直链模式允许为 false）
- `reportDir` 指向**当前**目录下的 `reports` → 说明路径自适应正常
- 打开 `/vendor/hls.min.js` 返回 413952 字节 → 播放内核就位

再访问 `http://127.0.0.1:8770/?demo=1` 载入演示通道，能出图即表示前端播放链路完好。

## 十二、打包为免安装可执行程序

目标主机没有 Python 时，用 PyInstaller 打成单个可执行文件，拷过去双击即可。

### 1. 构建（在开发机上做一次）

```bash
python -m pip install pyinstaller    # 仅构建机需要，目标机不需要
python build_exe.py                  # 生成 dist_exe/EzvizWall.exe
```

可选参数：

```bash
python build_exe.py --name 监控墙      # 自定义产物名
python build_exe.py --onedir          # 目录模式：启动更快，但不是一个文件
python build_exe.py --icon app.ico    # 指定图标
```

### 2. 产物

| 项目 | 实测值 |
| --- | --- |
| 路径 | `dist_exe/EzvizWall.exe` |
| 体积 | 8.1 MB（单文件，内含 web/ 与 hls.js） |
| 目标机要求 | 只需操作系统本身，**不需要 Python、不需要拷贝 web 目录** |
| 首次启动 | 比源码模式慢约 1 秒（单文件需先自解压） |

### 3. 路径分离（关键实现）

单文件 exe 运行时会把资源解压到一个临时目录（`sys._MEIPASS`），**该目录在进程退出后即被删除**。如果把 `config.json` 和 `reports/` 写在那里，用户填的凭证和生成的报告每次都会丢失。

因此服务端把两类目录严格分开：

| 目录 | 单文件模式下的位置 | 用途 |
| --- | --- | --- |
| 资源目录 `RES_DIR` | `sys._MEIPASS` | `web/` 静态文件，只读 |
| 数据目录 `DATA_DIR` | **exe 所在目录** | `config.json`、`reports/`，可写 |

源码运行时两者是同一目录，行为与之前完全一致。

实测验证（把 exe 单独拷到空目录后运行）：

```
启动前目录： EzvizWall.exe
启动后目录： EzvizWall.exe / config.json / reports/
/api/state  → reportDir: ...\exe_test\reports     ← 落在 exe 旁边，不是临时目录
/vendor/hls.min.js → 200, 413952 bytes            ← 来自包内，离线可用
```

结论：exe 可以单独拷到任意路径（U 盘、桌面、其他机器）直接使用，凭证与历史报告跟着 exe 走。

### 4. 已知事项

- 部分杀毒软件会对 PyInstaller 产物报"未知程序"，需加白名单；这是打包工具的普遍现象，与代码无关。
- 单文件模式每次启动都要解压约 8 MB，机械硬盘上可能感觉慢；对启动速度敏感时用 `--onedir`。
- `--onedir` 产物是一个文件夹，需要整体拷贝，不能只拷 exe。
- 打包产物与源码功能完全一致，`config.json` 仍以明文保存 AppSecret，请注意存放位置。
